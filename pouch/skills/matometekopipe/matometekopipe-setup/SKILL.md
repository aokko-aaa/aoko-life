# まとめてCOPIPE を、あなた用に作る

## はじめに（Claude が、作る前に必ず使う人へ伝えること）

作業を始める前に、次の注意書きを、この言葉のまま（または同じ意味で）使う人に伝えてください。

> このスキルには、まとめてCOPIPE のコードは入っていません。
> 作者がまとめた「どんなアプリか」「どう作るか」を読んで、**Claude があなた用に一から作ります**。
>
> - **見た目や細かい動きは、作者が使っているまとめてCOPIPEとは少しちがいます。** 同じ説明から作っても、作るたび・作る人ごとに、色や形、ボタンの言葉などが少しずつ変わります。
> - できあがったアプリは**あなたのもの**です。あなたの Cloudflare（無料プランで足ります）で動き、データもそこに置かれます。作者のアプリやデータとはつながっていません。
> - **見た目は、あなたの好みにアレンジして作ってみてください。** 作る前に、次のようなものを Claude に見せたり伝えたりすると、そのふんいきで作ります。
>   - トンマナ（色・形・ふんいき）の見本になる画像（チラシ、ロゴ、好きな雑貨の写真など）
>   - 使いたい色のカラーコード（例：`#97A8DC`）
>   - 参考にしたいサイトやアプリのスクリーンショット
>   - 「やさしい感じ」「レトロ」「シンプルで白っぽく」などの言葉
>
>   何もなくても作れます。そのときは、シンプルな見た目で作ります。
> - 直したいところがあれば、できあがってから Claude に言えば直せます。作者のアプリが新しくなっても、あなたのアプリは自動では変わりません。
> - Googleマップの保存リストは、Google の正式なものではない読み出し方で読みます。**Google 側が変わると、急に読めなくなることがあります。**
> - Cloudflare のアカウント作成・ログイン・支払いの設定は、あなたが自分でします（Claude はパスワードやカード番号を聞きません）。
>
> このまま作ってよいですか？

使う人が「はい」と言ってから進めます。返事はいつも日本語で、ですます・やわらかめの言葉で話してください。

## このファイルの置き方（使う人向け）

1. このファイルを `~/.claude/skills/matometekopipe-setup/SKILL.md` という名前で置きます（フォルダがなければ作ります）。
2. いっしょに配っている `cloudflare-setup.md` も、`~/.claude/skills/cloudflare-setup/SKILL.md` に置きます。
3. 空のフォルダを1つ作り、そこで Claude Code を開いて「まとめてCOPIPEを作りたい」と話しかけます。

## 進め方（Claude 向け）

1. 上の「はじめに」を伝えて、了承をもらう。
2. 本人に聞いて決める：
   - **Worker の名前**（アドレスは `https://<名前>.<サブドメイン>.workers.dev`。英小文字・数字・ハイフン。希望がなければ `matometekopipe`）。
   - **使い方**：ひとり用（ふつうはこちら。アドレスを知っている人は誰でも同じリストを見たり消したりできる）か、みんなに配る用（開いた人ごとに「自分用のアドレス」ができて、リストが分かれる）か。
   - **見た目の好み**。「トンマナの見本の画像」「カラーコード」「参考にしたいサイトのスクリーンショット」などがあれば、チャットに貼ってもらう（画像はドラッグするか貼りつければ Claude に見せられる、と伝える）。もらったものは、そのまま写すのではなく、このアプリに合うようにアレンジして使う。とくになければ、下の「見た目」のとおりに作る。
3. **cloudflare-setup スキル**で、ログインとアカウントを確かめる。
4. 下の「作り方」のとおりにコードを書く。
5. 手元で動かして確かめる（`npx wrangler dev`）。本物の保存リストの共有リンクを1つ本人にもらい、登録 → 一覧 → 地域 → 地図 → 選ぶ → コピー まで通ることを見る。
6. 同じ名前の Worker がないか確かめてから（`npx wrangler deployments list --name <名前>`）、D1 を作り、表を当てて公開する。
7. アドレスと、下の「使う人に伝えること」を本人に伝える。

## 作り方

### つくり

- Cloudflare Workers + D1 + 静的アセット（`public/`）。フレームワークなし、素の HTML / CSS / JS。ビルドの手順はなし。
- `wrangler.jsonc`：`main: "src/index.js"`、`assets: { directory: "./public", binding: "ASSETS", run_worker_first: ["/api/*"] }`（みんなに配る用は `"/u/*"` も）、`d1_databases` に `binding: "DB"`・`migrations_dir: "migrations"`。
- `package.json` の devDependencies に `wrangler`（そのときの最新を、版を固定して）。
- 表を変えるときは、`migrations/` に新しい番号の SQL を足す（当てたファイルは書きかえない）。
- 秘密の値（APIキーなど）は使わない。

### できること（画面）

スマホで使う前提の1枚の画面です。

1. **上の帯**：アプリの名前と、リストのタブ。タブは押すたびに「見る・見ない」が切りかわり、いくつでも重ねて見られる（3つ以上あれば「すべて」も）。最後に「＋ リストを足す」。
2. **保存リストを足す**：Googleマップの保存リストの共有リンク（`https://maps.app.goo.gl/…`）を貼って「登録する」。読めることを確かめてから登録する。下に「共有リンクの出し方」を書く（Googleマップの「保存済み」→ リストの「︙」→「共有」→「リンクを知っている人」が見られる形にしてコピー）。
3. **グーグルマップからコピペ**：Googleマップで場所の「共有」→「コピー」したもの（名前と URL が混ざった文）をそのまま貼ると、名前と URL を取り出して足せる。名前は手で直せる。ひとことメモも足せる。消すときは「消す」→「本当に消す」の2段。
4. **見せ方**：「一覧」「地域」「地図」を切りかえる。
   - 一覧：場所のカード（名前・住所・メモ・「マップ」へのリンク）。重ねて見ているときは、どのリストのものかも小さく出す。
   - 地域：都道府県（北から順）→ 市区町村 の見出しでまとめ、見出しごとに「まとめて選ぶ／まとめて外す」。
   - 地図：OpenStreetMap にピン。ピンを押すと名前と「選ぶ」ボタン。
   - 名前・住所・地域・メモで探せる欄。
5. **選ぶ**：カードを押すと選ぶ・外すが切りかわる（リストをまたいで選べる）。選んだら、下に「◯件えらび中」と「コピー」の帯が出る。
6. **LINE に貼るメモ**：「コピー」で、そのまま LINE に貼れる文がコピーされる。帯を押すと下からメモが出て、いちばん上の一行、「1. 2. 3.」か「・」、住所・メモ・URL を入れるかを選べ、手でも直せる。「コピーする」「LINEで送る」（`https://line.me/R/share?text=…`）「選んだものをぜんぶ外す」。
   - 形の例：`1. お店の名前` の次の行に URL、お店ごとに空行。
7. 見ているリスト・選んだもの・見せ方・メモの書き方は、その端末（localStorage）に覚えておく。
8. リストを外すとき（「外す」→ もう一度）は、「Googleマップのリストはそのままです」と伝える。
9. リロードマークで、そのリストをすぐ Google から読み直す。

### サーバー（`src/index.js`）

- `/api/*` 以外は `env.ASSETS.fetch(request)`。
- エラーは `{ error: "やわらかい日本語の文" }` で返し、画面はそれをそのまま出す。
- 置くもの：
  - `lists`：id, share_url, list_key（Google のリストID）, token（共有リンクの鍵）, title, snapshot（最後にうまく読めた中身の JSON）, synced_at, created_at。list_key は重ならないように。
  - `places`：グーグルマップからコピペした場所。id, name, url, memo, lat, lng, created_at。
  - `geo_cache`：key（緯度,経度 を小数4けた）, pref, city。
- API：
  - `GET /api/state` → 登録したリスト（id, title）と、コピペした場所。
  - `POST /api/lists { url }` → 共有リンクを読んで登録し、中身も返す。
  - `GET /api/lists/:id/places` → リストの中身。**12時間以内に読んだものは snapshot を出し、Google を呼ばない**（リストはそう頻繁に変わらないし、呼びすぎると断られる）。`?force=1` のときは必ず読みに行く。Google に断られたら、snapshot があれば黙ってそれを出す。
  - `DELETE /api/lists/:id`、`POST /api/mine { url, name, memo }`、`DELETE /api/mine/:id`。
  - 数の上限を置く（リストは20個、コピペした場所は300件くらい）。
- **保存リストの読み方**（Google の正式なものではない）：
  1. 共有リンクを `redirect: "manual"`、`user-agent: "Mozilla/5.0"` でたどる（6回まで）。たどるのは Googleマップのホスト（`maps.app.goo.gl`, `goo.gl`, `www.google.com`, `google.com`, `maps.google.com`, `www.google.co.jp`, `google.co.jp`, `maps.google.co.jp`）の https だけ。ほかのホストは読まない。
  2. URL の中の `!2s<リストID>!` か `/placelists/list/<リストID>` からリストIDを、`token%3D…` か `?token=…` から鍵を取り出す。
  3. `https://www.google.com/maps/preview/entitylist/getlist?authuser=0&hl=ja&gl=jp&pb=!2e2!3e2!4i500!6m3!1s<ランダムな22文字>!15i204459!28e2!13s<encodeURIComponent(リストのページのURL)>!16b1` を、ふつうのブラウザの user-agent と `accept-language: ja` で呼ぶ。リストのページの URL は `https://www.google.com/maps/placelists/list/<リストID>?token=<鍵>`。
  4. 返ってきた文の先頭の `)]}'` を取って JSON にする。`data[0][4]` がリストの名前、`data[0][8]` が場所の配列。場所ごとに `[2]` が名前、`[3]` がメモ、`[1]` が情報で、`[1][4]` が住所、`[1][5][2]`・`[1][5][3]` が緯度・経度、`[1][6]` の最後の数がお店の番号（CID。負の数なら 2^64 を足す）。URL は CID があれば `https://maps.google.com/?cid=<CID>`、なければ `https://www.google.com/maps/search/?api=1&query=<名前 住所>`。
  5. 429 のときは「Googleが混み合っていて、リストを読めませんでした。少し時間をおいて、読み直してください」。読めないときは「リストの共有が『リンクを知っている人』になっているか確かめてください」。
  6. 読めなかったときは、返ってきた中身の先頭を `console.log` に出しておく（`wrangler tail` で見るため）。**配列の位置は Google 側で変わることがある**ので、読めなくなったら、まずここを確かめる。
- **コピペした場所の読み方**：URL を同じ Googleマップのホストだけ5回までたどり、`!3d緯度!4d経度`（なければ `@緯度,経度`）で位置、`/maps/place/<名前>/` か `?q=` で名前を取る。
- **市区町村**：国土地理院の逆ジオコーダー `https://mreversegeocoder.gsi.go.jp/reverse-geocoder/LonLatToAddress?lat=…&lon=…` で市区町村コードを聞き、`https://maps.gsi.go.jp/js/muni.js` で名前に直す（政令市は区を落として市までにそろえる）。聞いた結果は geo_cache に覚える。**Worker は1回に外へ出せる数に上限があるので、1回で聞くのは30件まで**。残りの数を返し、画面は少し待って読み直す（そのとき Google は呼ばない）。決まった URL だけを呼び、貼られた URL は渡さない。

### みんなに配る用にするとき（ひとり用なら飛ばす）

- 環境変数 `MULTI="1"` のときだけ、人ごとに分ける。
- 「/」を開いたら「自分用のアドレスを作る」ボタン。押すと `crypto.randomUUID()` から作った32けたの英数字で `/u/<鍵>` に移る。端末に鍵を覚えておき、次に「/」を開いたらそこへ移る。
- `/u/<鍵>` は Worker が同じ画面を返す。manifest も `/u/<鍵>/manifest.webmanifest` で人ごとに出し、`start_url` を `/u/<鍵>` にする（ホーム画面から開くと自分のページになるように）。
- 画面は鍵を `x-key` ヘッダーで送る。Worker は鍵の SHA-256 から作った `owner` を lists・places に入れ、**すべての読み書きを owner で絞る**。lists の「重ならない」は owner ごとに。
- 「リストを足す」の下に、自分用のアドレスとコピーのボタン。「なくすと戻れません」「人には教えないでください」と書く。

### 見た目

- 使う人がくれたトンマナの見本・カラーコード・参考サイトのスクリーンショットがあれば、そこから色（地の色・線・選んだもの・ボタン）、書体のふんいき、角の丸さ、飾りを読みとって、このアプリに合うようにアレンジする。参考サイトのロゴや文章、画像そのものは使わない（ふんいきだけを借りる）。色は `:root` の CSS 変数にまとめ、あとから一か所で変えられるようにする。作ったら、どこをどう取り入れたかを一言で伝える。
- 見本がなければ：明るい1種類だけ。落ち着いた地の色に、黒いインクのような 1.5px の線、選んだものは青。手書き風の見出しの書体（Google Fonts）。
- 名前・件数・「コピー」は大きく。
- スマホで使う前提：押すところは高さ40px以上、入力欄の文字は16px（iPhone で勝手に拡大されないように）、画面のはしに16pxの余白、横にはみ出さない。
- `manifest.webmanifest` とアイコン（192・512・apple-touch-icon）を用意し、ホーム画面に追加できるようにする。アイコンは、本人に画像があれば使い、なければシンプルなピンの形を作る。

### 安全のための決まり

- 画面に出す値は `textContent` か、`& < > "` を置きかえてから。
- URL を `href` に入れるのは `https?://` で始まるときだけ。
- 入ってきた文字は長さを切る（名前80字、メモ300字、URL600字くらい）。

## 使う人に伝えること（公開したあと）

- アドレス。iPhone は Safari で開いて共有ボタン →「ホーム画面に追加」、Android は Chrome の「︙」→「ホーム画面に追加」。
- ひとり用：アドレスを知っている人は誰でも見たり消したりできるので、広めないこと。
- みんなに配る用：「自分用のアドレスを作る」を押して `/u/…` になってからホーム画面に追加すること。そのアドレスをなくすと戻れないこと。
- リストは、Googleマップの共有で「リンクを知っている人」が見られる形にすること。
- 登録したばかりのリストは、Googleが混み合っていて少し待つことがあること。
- 読み出し方は Google の正式なものではないので、急に使えなくなることがあること。
- **作者のアプリとは見た目が少しちがうこと、直したいところは Claude に言えば直せること。** あとからでも、トンマナの見本やカラーコード、参考サイトのスクリーンショットを見せれば、見た目をアレンジし直せること。

## うまくいかないとき

- **リストが読めない**：共有が「リンクを知っている人」になっているか。
- **「混み合っています」**：Google が Cloudflare からの読み出しを断っている（429）。時間をおいてリロード。
- **ずっと読めない**：`npx wrangler tail <名前>` でログを見て、上の「保存リストの読み方」の配列の位置が変わっていないか確かめる。
- **Cloudflare のエラー（ログイン・権限・サブドメインなど）**：cloudflare-setup スキルの「よくあるエラー」を見る。
